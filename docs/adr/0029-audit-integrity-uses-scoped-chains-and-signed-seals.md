# 审计完整性使用分流哈希链与签名封存

一期按Task、Case和System边界维护独立的追加式审计流，而不是以全局串行日志作为真值；每条流中的Audit Event以版本化规范字节、前序事件摘要和自身摘要形成哈希链。每个UTC日的事件集合，以及进入终态的Analysis Task、报告批准和保留销毁操作，都生成包含Merkle根的签名审计封存并写入WORM对象存储。该设计既支持并行分析性能，也能使数据库或业务对象存储被篡改后被独立验证发现。

## Consequences

签名由独立于应用、PostgreSQL和业务对象存储权限的Audit Sealer持有；一期使用可替换的签名提供者和独立挂载的密钥，后续可接入KMS或HSM。受限模型正文不能写入WORM桶，因为它必须在Case归档后180天按策略销毁；正文在专用受限桶中保持内容寻址、加密和禁止覆盖，只有保留服务可按策略删除，签名封存、对象摘要、来源关系和销毁事件则长期保留。原始样本、派生Artifact、ToolRun原始输出和Evidence所依赖内容不适用该180天策略，一期不自动清理；其未来不可逆处置必须在Case归档后通过Case证据销毁Gate，并保留所有影响报告的历史核验关系。共享Content Blob的处置先撤销本Case引用，只有所有Case均无未处置引用时才物理回收字节。外部发布Gate只能批准完整性核验通过且已有对应审计封存的Analysis Snapshot。
