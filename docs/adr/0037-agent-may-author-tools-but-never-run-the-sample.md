# ADR-0037：分析系统可自主创建缺失工具，但不得执行样本

状态：已接受（2026-09-16）  
取代范围：收窄 ADR-0031「phase-one keeps DSH host tools closed」中「模型不得为自己创造新工具」的部分。  
仍然有效：ADR-0031 关于「不把宿主 shell/网络交给模型」、ADR-0019「静态工具运行在隔离 worker」、ADR-0020「不可信分析数据不能授权动作」。

## 背景

用户要的最终形态是：**分析系统遇到自己解决不了的问题时，自主选择解决方式，包括自己创建工具来完成目标，而不是完不成就跳过难点**。用户提供的 `peinfo` 工具包正是这种能力的产物——它是另一个 Agent 在反复分析样本过程中自我迭代长出来的。

当前产品的缺口在两侧：

- 后端调查循环的动作是**闭集** `ActionType`（GET_DECOMPILE / TRACE_API_ARGUMENT / CONTROLLED_EMULATE …）。缺口映射 `recovery_actions_for_gap` 找不到动作时，线程只能停在 `UNKNOWN` 或 `STATIC_BOUNDARY`。
- 产品已内置「受控模拟占位不得当已尝试」的诚实门，但**没有**「这条缺口需要一种还不存在的能力」的表达方式，更没有把它造出来的路径。

结果是：能力边界由代码写死的枚举决定，而不是由样本实际需要什么决定。

## 决定

产品新增**工具创作（tool authoring）**能力，作为受控模拟之外的第二条自主扩展路径。它遵守下列不可协商的约束：

1. **绝不执行样本。** 创作出的工具不得启动、加载或以任何方式运行提交的恶意样本本体或其释放物。静态分析、数据流恢复、对授权字节窗口的隔离模拟仍按既有契约执行。这是唯一由用户明确划定的硬边界，且与既有「静态分析 / 受控模拟 / 不做动态分析」的术语分工一致。
2. **工具只读样本字节，不触网。** 创作工具在既有隔离 worker 契约下运行：无网络、只读根文件系统、`cap_drop ALL`、临时输出目录、CPU/墙钟/指令上限。禁止访问样本中的 URL/IP。
3. **工具是声明式产物，不是宿主 shell。** 模型提交的是结构化工具规格（名称、用途、输入选择器、确定性实现、输出 schema、失败模式），由编排器裁决后在 worker 内执行。模型**不**获得交互式宿主 shell，也不获得把任意命令直接投放到 API 进程的能力。
4. **每次创作都要过策略门与审计。** 工具规格、来源缺口、执行记录、原始输出与输入摘要进入追溯链；工具源码属于受限审计载荷，可复现、可撤销。
5. **产物是证据，不是结论。** 创作工具的输出按 `STATIC_DERIVED`（或隔离模拟时的 `EMULATION_OBSERVED`）落 Evidence，且仍需经既有 Claim Gate 与行为证据契约判定；不得因为「是我们自己造的工具算出来的」而提升结论强度。
6. **失败必须留下方法。** 工具创作失败要记录已试方法、失败原因与下一步，不允许把它当作「已尝试过所以可以跳过」，也不允许据占位写 `STATIC_BOUNDARY`。
7. **可复用要过晋升门。** 一个被证明有用的创作工具要进入常备工具集，必须经过知识晋升 Gate：检查适用范围、反例、版本与证据独立性。`peinfo` 就是这种晋升的产物，属于同一模式的既有先例。

## 结果

- 调查循环新增「缺口无既有动作可解」的表达与对应动作类型，缺口不再只能收敛到 UNKNOWN。
- 工具策略层新增创作工具的准入判定（无网、不执行样本、资源上限、只读输入）。
- 分析报告在「分析限制」中区分三种停法：镜像内可恢复槽未恢复（失败）、运行时事实 UNKNOWN（允许）、以及已真实尝试且工具创作也未能解决的具体阻塞。

## 不做什么

- 不把宿主执行权交给模型（ADR-0020 不变）。
- 不用「模型自己写了脚本」替代既有静态分析或受控模拟路径；创作只在既有路径确实无法回答该缺口时才被提出。
- 不引入外部查询（样本信誉库等）作为创作工具的默认能力。
